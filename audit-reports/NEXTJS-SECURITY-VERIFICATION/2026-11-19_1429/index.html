Request smuggling in rewrites (GHSA-ggv3-7p47-pfv8)

FIXED · VERIFIED  In a 127.0.0.1-only harness, next 16.1.6 put a hidden second request on the backend connection after content-length: 0. next 16.4.6 kept it inside the chunked body. This app has no external rewrite, so it was not exposed even on 16.1.6, and its server rejects all 11 Content-Length / Transfer-Encoding conflict cases with 400. Read the verification
